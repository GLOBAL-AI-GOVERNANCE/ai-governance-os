# Frontier AI Protocol

Frontier systems require temporary authorization under evidence. They are not permanently trusted.

## Gate 1: Capability Forecasting

Identify what new capabilities the system may create, including autonomy, long-horizon planning, tool use, code execution, cyber assistance, persuasion, scientific reasoning, biosecurity relevance, and strategic decision support.

## Gate 2: Truth and Verifiability

Assess whether the system improves, degrades, or obscures verifiable understanding. Require source grading, confidence labels, citation checks, and evidence hierarchy for decision-facing outputs.

## Gate 3: Access Control

Apply least privilege. Block unrestricted external actions. Limit write access, payments, email sending, code execution, procurement actions, and sensitive data access unless explicitly approved.

## Gate 4: Independent Red Teaming

Test for misuse, hallucination, prompt injection, deception, goal-hacking, unsafe autonomy, cyber misuse, privacy failure, and strategic overclaiming.

## Gate 5: Staged Deployment

Move through lab testing, closed beta, limited release, monitored release, and scaled release only when evidence supports expansion.

## Gate 6: Live Monitoring

Monitor tool calls, output quality, abuse patterns, unsafe autonomy, data exposure, prompt injection, model drift, and truth-verifiability concerns.

## Gate 7: Incident Response

Prepare containment, credential revocation, log preservation, harm assessment, notification, correction, and reauthorization.

## Gate 8: Reauthorization

Reopen review after model updates, new tool access, serious incidents, new user populations, new data categories, major capability improvement, deception, goal-hacking, or truth-verifiability degradation.
